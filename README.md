# Bid Estimation App (MVP)

Takes a manual baseline staffing timeline plus information about a bid and returns the AI productivity gain per role,
the AI-adjusted effort, the token cost range, a calculated AI timeline and an Excel comparison report.
Implements `Bid Estimation App — MVP Specification v0.2`.

## Run it

```bash
npm install
cp .env.example .env.local   # then set ANTHROPIC_API_KEY (only needed for RFP pre-fill)
npm run dev                  # http://localhost:3000
```

Without an API key everything works except the RFP pre-fill; the survey is then answered manually.

| Command | What it does |
|---|---|
| `npm run dev` | Start the app (single process: UI and API) |
| `npm test` | Unit tests, including the spec's worked example (section 11) and boundary checks |
| `npm run typecheck` | TypeScript check |
| `npm run build && npm start` | Production build |
| `npm run fixture` | Regenerate `tests/fixtures/timeline-template.xlsx` |

## Technology stack and why

**Next.js (App Router) + TypeScript, one package.** The calculation must run instantly in the browser (under 200 ms
after every input change) *and* on the server for the Excel export. A single TypeScript codebase lets both use the
same pure module (`lib/calc.ts`), and Next.js gives the UI and the few server routes (RFP text extraction, LLM call,
timeline parsing, export) in one process started with one command. It also matches the stack already used by the
`frontend/` app in this repository.

Libraries: `exceljs` (read the timeline, write the report), `unpdf` and `mammoth` (PDF / DOCX text), `@anthropic-ai/sdk`
with `zod` (structured survey pre-fill), `vitest` (tests). The chart is plain SVG.

## Behaviour notes

- **Bid state** is kept in the browser's `localStorage` (one bid at a time); "New bid" clears it. RFP files are held in
  memory only so the pre-fill can be re-run; after a page reload, upload the RFP again to re-run it.
- **RFP handling:** text is extracted in memory on the server and sent to the LLM; nothing is written to disk.
  The prompt treats the RFP as untrusted data and instructs the model to ignore instructions inside it.
- **LLM settings** (`.env.local`): `ANTHROPIC_API_KEY` (server only, never sent to the browser), `BID_PREFILL_MODEL`
  (default `claude-opus-5-5`), `BID_PREFILL_FALLBACKS` (`default` enables the API's server-side refusal fallback;
  `off` disables it — set `off` if you switch to a model that does not support it).
- **Week columns** are identified by position between `Role` and `Total`; `#`, `Domain` and `Total per Tech Domain`
  are ignored wherever they appear. All totals are recomputed (this corrects the template's `SUM(I:AF)` bug).

## Test fixture

The real Timeline Template was not available while building this, so `tests/fixtures/timeline-template.xlsx` is a
reconstruction generated by `scripts/make-template-fixture.ts`. It reproduces the template's documented layout and quirks
(repeating week labels, the truncated `Total` formula, `#REF!` in `#`) and the reference figures (11 lines, 28 weeks,
1,610 PD). Run the real template through the app once to confirm the parser handles it.
